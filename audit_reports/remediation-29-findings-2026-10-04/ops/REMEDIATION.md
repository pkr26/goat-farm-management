This scope implements **O26-01, O26-02, O26-03, O26-04, O26-07, O26-08 and O26-09**. The original audit is unchanged. Changes are local source/configuration updates; no production service, provider, registry package, release or real farm data was changed.

## Image identity and architecture validation

The accepted PostgreSQL runtime is `goatfarm-postgres:16-security-20261004`, built from the pinned upstream image plus exact-hash security packages. A raw upstream base is not being represented as that remediated runtime. Production Compose uses external PostgreSQL, whose deployed patch policy remains outside this local test. GitHub Actions' disposable PostgreSQL service pins were refreshed to the same upstream digest; they are distinct from the derived local runtime and do not receive a claim of a clean derived-image scan.

The repository keeps its existing HIGH/CRITICAL, fixable-only policy. **A passing scoped gate does not mean zero total vulnerabilities.** The accepted PostgreSQL image still includes the previously acknowledged upstream gosu Go records and unfixed distro advisories in the raw inventory. Backend/frontend/edge scans never load the PostgreSQL exception file. The 30-day exception review deadline remains enforced.

The first two AMD64 frontend builds completed compilation, TypeScript and route generation, then aborted in Node/libuv at teardown with `Assertion failed: errno == EEXIST ... uv__io_poll`. [First attempt](frontend-amd64-build.log) and [focused rerun](frontend-amd64-focused-rerun.log) are retained. The independent frontend reviewer [reduced the failure to loading native sharp in the Next configuration process](../frontend/amd64-build-diagnosis.md), confirmed an invalid epoll descriptor, and isolated that version probe in a bounded child process while preserving the fail-closed security policy. The final full ARM64 and AMD64 builds, standalone/native-library checks and vulnerability scans all pass. AMD64 ran under local QEMU; a native release runner and registry publication were not invoked. No product default, exit-code handling or security gate was weakened to conceal the earlier failure.

The local classic Docker builder also mislabels some cross-architecture intermediate ENV/COPY layers. The saved AMD64 backend/frontend probe Dockerfiles resolve each committed immutable index to its exact AMD64 child from [the verified registry indexes](resolved-image-pins.json); application source and build instructions are otherwise identical. This is recorded as a local validation mechanism, not a change to the shipped Dockerfile. Final build-input hashes are retained in [final-build-input-sha256.json](final-build-input-sha256.json); [the previous snapshot](pre-probe-isolation-build-input-sha256.json) preserves provenance for the earlier frontend image. The final snapshot matches the current source.

The aborted build containers retained idle pnpm parents and two 3 GB core files. [Exact owned-container cleanup](aborted-amd64-container-cleanup.json) removed them without touching databases; a subsequent [read-only PostgreSQL capacity/health check](docker-capacity-recovery.json) passed with over 16 GB free. Root records the independent full-suite infrastructure failures and reconciliation separately; the retained container logs did not prove their exact cause.

[Final cleanup](cleanup-final.json) removed 2.47 GB of owned scanner/image-export/tool scratch and edit scaffolding after verifying retained raw reports and SBOM hashes. All eight accepted image tags and the original diagnostic input image remain available for review. The exact owned host test database is absent, and no task-owned container is running. No global prune or user-database cleanup was performed.

## Deployment follow-through

Provision the purpose-specific metrics token in the worker's own secret directory as well as the API's directory, and attach the scraper to the private worker network. Do not share the API secret directory with the worker. This is described in the updated Compose environment example and operations runbook.

The freshness systemd service now reads `/etc/goatfarm/backup-freshness.env`. Configure the independently verified signer fingerprint and a readable public-key-only GPG keyring. Capture inventories with the actual `--object-recovered-at` timestamp. Schema-v1 unsigned inventories are deliberately not automatically trusted: establish a fresh complete v2 backup before relying on the new monitor, and preserve historical archives for separately reviewed provenance recovery with their original component times. The database encryption/signature requirement remains intact.

No production deployment, live provider call, remote backup upload, alert delivery, registry release or real-data restore was performed. Those external operational checks retain their normal deployment responsibility.
