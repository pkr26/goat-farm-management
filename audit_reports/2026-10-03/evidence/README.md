The Python probes are deliberately small reproductions of specific observed defects. `herdly-domain-audit-probes.py` uses mocked provider/storage behavior plus a disposable database. The insurance-lock, sale-weight-calibration, screening-review, owner-aggregate, cadence-isolation, mortality-calibration and dashboard-permission probes each create a UUID-named database on local PostgreSQL, populate invented records with SQLAlchemy model metadata, and force-drop that database in `finally`. They require local database creation privileges and the project's backend environment. They do not connect to the application's ordinary database. Model-metadata setup establishes application behavior against PostgreSQL, rather than proving every migration history.

`herdly-simulation-extension-probes.py` exercises pure calculations. `herdly-health-round-audit-test.py` depends on existing backend pytest fixtures and the application's real test API; it must run with an explicitly unique `GOATFARM_TEST_DB` and the repository's test configuration. Do not treat it as a standalone script. The audit used an isolated test database; no production or ordinary development data was used.

`herdly-offline-probe.cjs` transpiles the actual queue and API-client modules into a VM with mocked browser storage and mocked fetch. Its `opaque-token` and provider keys are invented fixtures. It establishes queue behavior without issuing real HTTP requests. `herdly-worker-setup-probe.json` and `herdly-planner-conflict-probe.json` are captured output from targeted source-function harnesses, rather than independently runnable programs.

The two `.test.tsx` probes use the repository's Vitest/MSW environment. To reproduce the domain-page probe, temporarily place it under `frontend/src/test/` and run that one test file with the existing configuration. The worker-handover probe has a relative `./layout` import and belongs beside `frontend/src/app/worker/layout.tsx`. Remove temporary copies after verification. These tests assert the observed bad behavior; a successful test means the defect reproduced, not that it was fixed. They are evidence artifacts, not additions to the shipped test suite.

Several scripts intentionally preserve the audit workstation's absolute project path. Update that base path before reproducing on another checkout. All probes import the current checkout, so results after source changes can differ. Run only against a disposable local PostgreSQL instance. An abruptly terminated process can bypass normal cleanup; verify and remove only its explicitly named UUID audit database if that occurs. No probe was automatically executed when this bundle was prepared.

Logs and evidence were checked for private-key blocks, JWT-shaped tokens, common provider/access-key prefixes, credential-bearing URLs, and credential-related contexts before copying. No real credentials were found in the copied material. Live server logs, environment files, the E2E credential state file, exported requirements, and virtual environments were excluded. Screening-provider probes use mocks and do not spend provider quota; the evidence does not send real messages or payments.

The NLM policy PDF is linked directly from its official DAHD source in the backend extension report and is not duplicated here. Remaining external primary-source links require network access. Local evidence references in the contributor reports were moved from temporary locations to this preserved directory. The extension's earlier assertion of exhaustive manual test-source review was corrected: the project audit executed the complete existing suites and inventoried test files mechanically, while selected tests received manual review.

`manifest.json` records byte sizes and SHA-256 digests of the complete report bundle, including the main report, coverage ledger, contributor reports and evidence. It excludes itself to avoid a circular digest. These receipts support the audit's conclusions and stated limitations; they are not production load, disaster recovery, veterinary accuracy, or security certification results.

`mutation-context-check.json` records the read-only compiler/manifest check behind BM-07; no mutation tool was executed. `final-validation.log` records the final local-link, source-diff and score checks.
