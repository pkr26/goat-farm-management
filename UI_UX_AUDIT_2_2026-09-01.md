# PashuFarm UI/UX Re-Audit — 2026-09-01

> **Brand note (2026-09-01, later the same day):** the product was renamed **PashuFarm → Herdly** after this audit and remediation. "PashuFarm" below refers to the app as it was named during the audit; all brand surfaces (wordmark, document titles, export filenames, README) now read Herdly. Internal identifiers (`goatfarm.*` storage keys, env vars, DB name, API paths) were deliberately kept stable so no session or deployment breaks.

**Goal measure:** "One of the best UI/UX experiences in the industry" — benchmarked against Linear / Stripe / Vercel-grade product surfaces, not against "acceptable admin panel".

**Context:** This is the second full UI/UX audit. The first (`UI_UX_AUDIT_REPORT.md`, 2026-08-31, overall ≈ 5.5/10) was followed by the "full UI/UX redesign" (commit `3cf4659`) and the RBAC/milk-quality commit (`c25894d`). This re-audit assesses **the current tree skeptically**: every remediation claim was re-verified against code and a live browser, and everything shipped after the redesign was audited with fresh eyes.

**Method — four independent evidence channels, cross-verified:**
1. **Design-system code audit** — full read of tokens (`globals.css`), fonts (`layout.tsx`), all shared components and UI primitives.
2. **Three adversarial verification sweeps** (prior-findings regression check · newest-feature adherence · mobile/a11y) covering all 18 module pages with file:line evidence.
3. **Live browser walkthrough** — real rendered app at 1440×900 and 390×844, dark and light themes, both farm types: login → goat farm (8 animals) → every module → add-animal dialog → theme toggle → mobile → farm-select → **buffalo dairy created live through the UI** → dairy dashboard → milk page with seeded fat-% records.
4. **Expert visual critique** of the captured screens via a vision model (login, dashboard, animals, simulation, milk scored; remaining screens assessed from DOM + code).

**Environment:** backend + frontend running locally (`:8000` / `:3000`), `goatfarm` Postgres migrated to head (f8a2c4e6b1d9), account `audit@goatfarm.test`, goat farm "Navipet Osmanabadi Farm" (8 animals) + dairy "Audit Murrah Dairy" (3 Murrah buffalo, 3 milk readings with fat %) created for this audit.

## 1. Executive summary

**Overall today: ≈ 6.5 / 10 — up from 5.5, on a genuinely higher foundation.**

The redesign was real, not cosmetic. The token system is complete and enforced (zero raw palette classes in runtime code), one status-chip system replaced seven, typography has an identity (Fraunces display + warm-paper light / green-black dark), the shell is species-aware end to end, onboarding exists, and the dialog/button conventions hold under adversarial checking. The prior audit's P0s (onboarding, charts-on-dashboard, species vocabulary in the shell, enum humanization) are mostly or partially resolved, and the two commits after the redesign largely respected the system.

What still separates this from "best in industry" is no longer consistency — it's **depth**:

1. **Perceived speed.** Every in-page data load in the app (≈74 occurrences across 27 files) is still a centered "Loading…" paragraph; page headers unmount during loads. The skeleton kit exists but three of its four exports are dead code. At the target tier this is the single most felt gap.
2. **Insight.** The chart kit ships `Sparkline`, `BarList`, `Donut` — only the Donut is used. There is still no trend line, no P&L chart, no lactation curve on the milk page, no real histogram for the Monte-Carlo NPV. A finance product is showing tables where the industry shows pictures.
3. **The field (mobile).** No table has a card fallback below `sm`; 10+ wide tables (up to a 19-column cashflow) squeeze or scroll inside a 390px viewport; primary row actions and tabs run 28–32px touch targets.
4. **Species depth in forms.** The Add-animal dialog — the first form every user touches — still defaults Breed to "Osmanabadi" and tag prefix "G-" on a buffalo dairy, lists buckets as raw codes (`QUARANTINE`, `FOUNDATION`, `BREEDING`), and validates with goat thresholds + "doe/buck" copy (10 months / 22 kg) where buffalo gates are 22–24 months / 340 kg.
5. **Simulation remains a wall** (2,979px measured with data): the sticky navigator helps, but there's no run bar, no basic/advanced tiering, and at least one dev-speak string ships in UI copy ("mirroring the backend defaults payload", `simulation/page.tsx:3163`).

The encouraging part: items 1–3 are systems work with outsized leverage — the primitives already exist (skeletons, chart kit, table primitives), they are simply not wired in.

## 2. Verified: what the redesign genuinely delivered (don't redesign away)

Every claim below was re-verified in the current tree, most also live in the browser:

- **Token discipline holds.** Zero raw Tailwind palette classes in any runtime page/component (only in test fixtures). `emerald/red/amber` fully gone; the two prior dark-mode breakages fixed.
- **One status system.** `StatusBadge` (dot + semantic tone + Title Case, `status-badge.tsx`) with superset enum coverage; the seven competing implementations are gone. Both prior casing wars are settled.
- **Dialog contract.** Cancel-left/confirm-right holds everywhere a Cancel exists; errors sit above footers; destructive variants only on genuinely destructive confirms (one borderline: tasks "Skip task").
- **One primary action per view** — verified across all 18 module pages; row actions are outline/ghost.
- **Tables** all render through the shared primitive with `table-numeric` (tabular figures) at the root; wide-table min-widths and shared pagination landed on animals/health/breeding/finance/kidding/team.
- **Species-aware shell** — verified live on a real buffalo dairy: sidebar shows "Breeding / AI" and "Calving", Milk appears only for dairies, dashboard says "Calvings due or overdue", buckets read "Milking — Pregnant 1–5 mo / Dry / Close-up + Calving Pens / Fresh Buffalo Pen". The weaning duties surface as "Calf-shed Attendant", never `CALF_ATTENDANT`.
- **Onboarding exists and is correctly gated** (empty-herd-only, wound-down herds excluded): a 3-step linked card, verified live on the fresh dairy.
- **A11y wiring** — aria-invalid/describedby/role=alert discipline across hundreds of fields; RemotePicker still exemplary; lucide icons auto-aria-hidden; zero onClick-on-div; permission-withheld sections never render as false "None." states (genuinely rare discipline).
- **Per-route document titles** (live-verified: "Dashboard · PashuFarm", "Calving · PashuFarm"), reduced-motion guard, single live region for route loading.
- **Milk fat-gate UX (newest commit) is done right** — disabled field explained with a label suffix + `aria-describedby` help line, not left silent.

## 3. Findings

Severity: **P0** = blocks the "best in industry" claim · **P1** = major visible gap · **P2** = consistency/polish · **P3** = nit.
(Paths under `frontend/src/`.)

### A. Experience & depth

**F-1 · P0 — In-page loading is still a text paragraph on every page; headers unmount during loads.**
~74 "Loading…" text occurrences across 27 files (dashboard:138,163; finance:665,688; animals:1060,1155; team:1165,1188; milk:148,329,390; health ×5; simulation ×5 …). Because the loading early-returns happen **before** `<PageHeader>`, the page title + primary action flash away on every visit — the exact half of prior F-U4 the remediation did *not* land. The skeleton kit (`skeletons.tsx`) is consumed only by the route-level `loading.tsx`; `CardSkeleton`/`StatSkeleton`/`TableSkeleton` are dead exports.
**Fix:** mount the header before data settles, render `TableSkeleton`/`CardSkeleton` in the data region of every list page, and adopt one inline loading treatment for sub-regions.

**F-2 · P0 — No insight visualization: chart kit 2/3 dead code, no trends anywhere.**
Only `Donut` is consumed (dashboard herd composition, `dashboard:614`). `Sparkline` and `BarList` have zero call sites; `StatCard.footer` (sparkline slot) unused; chart tokens (`--chart-1..5`) used by Donut only. Consequences, verified live:
- Milk page (vision verdict 6.5/10): "form-first, not insight-first — no lactation curve for an animal, no kg-fat derived metric, no per-shift breakdown visual" in a product whose backend literally models the Wood lactation curve.
- Simulation NPV distribution still isn't a real chart; P&L is tables only.
- Dashboard stat cards show state, not trajectory (no deltas/sparklines).
**Fix:** wire the existing kit + one axis-based chart (SVG or Recharts): StatCard sparklines + deltas, finance monthly P&L bar/line, milk lactation curve per animal, NPV histogram with percentile bands.

**F-3 · P1 — Add-animal dialog is species-blind where it matters most (verified live on a buffalo dairy; vision verdict 6.5/10).**
- Bucket dropdown options render **raw enum codes**: `QUARANTINE`, `FOUNDATION`, `BREEDING` (live-verified; the label maps exist in `enum-labels.ts` and the dashboard uses them — this select bypasses them). Vision critique: "a classic backend-leak… a buffalo dairy operator thinks 'the sick pen', 'milking herd', 'heifers'".
- Breed field **defaults to "Osmanabadi"** (a goat breed) and the tag placeholder says "e.g. **G**-7KP2D" on a Murrah dairy. Vision critique: "a prefilled value masquerading as user input… a user who doesn't notice will save animals with wrong breed metadata, corrupting every downstream report — for the target user, that's the most expensive flaw on the screen."
- Client validation hardcodes goat biology and nouns for all farm types (`animals/page.tsx:241-264`): "A **buck/doe** must be at least 10/12 months old", "Entry weight must be at least 22/25 kg" — the buffalo gates are 22–24 months / ≥340 kg (the app's own `breedingGateCopy` says so). A dairy user either sees wrong numbers or gets backend rejects the form promised were valid.
- Dialog footer has **no Cancel button** (Save only + X); required-field asterisks carry no "* = required" legend; the tag-number placeholder over-explains and truncates mid-sentence.
- Farm-select name placeholder ("e.g. Navipet Osmanabadi Farm") is goat-flavored for dairy users.
**Fix:** species-aware defaults (breed, tag prefix), `enumLabel("bucket", …)` in every bucket select, farm-type-parameterized validation messages/nouns, Cancel + asterisk legend.

**F-4 · P1 — Mobile remains desktop-with-scroll (mobile dashboard vision verdict 6/10).**
- No table in the app has a card fallback below `sm` (verified: the only `hidden md:*` toggles are the sidebar/auth/logout label).
- 10+ tables with >5 columns have no `min-w-*`: tasks (6–8 cols), purchases (10 cols), feeding plan (9), vaccination schedule (6), animal health events (6), feed inventory (5–6), and 9 simulation tables including a **19-column cashflow** (`simulation:2566`).
- Touch targets: row actions and pagination are 32px (`h-8`), tabs triggers ≈28px — below the 40–44px field-use guidance; `xs`/`icon-xs` (24px) exist but are unused.
- Verified live at 390px: animals table is 760px wide inside the viewport — horizontal pan with no affordance.
- Mobile dashboard critique: passive stats outrank actionable alerts ("the app leads with numbers to look at, not work to do"); a 2-up stat grid leaves an **orphaned fifth card** breaking the rhythm; a fully-red overdue card of 8 near-identical quarantine rows reads as alarm fatigue (should group/summarize); overdue task rows **truncate at the viewport edge** mid-sentence ("(Purchase #1) Days 1…").
**Fix:** card fallback for the 5 widest tables below `sm`; min-widths on the rest; ≥40px hit areas for primary row actions; mobile dashboard ordering (alerts → today → stats) and row truncation with ellipsis + count.

**F-5 · P1 — Simulation: still a 2,979px single-scroll wall (measured with data).**
The sticky section navigator (landed in the redesign) helps, but the vision verdict (5.5/10) captures the residual: "uniform density — every field gets the same visual weight, so nothing is skimmable… no sticky run bar… three ways to initialize state (Calibrate from farm / Load defaults / Use current herd) with no differentiation." Plus shipped dev-speak: "Model inputs grouped by section, **mirroring the backend defaults payload**" (`simulation:3163`).
**Fix:** tab/step structure with a sticky Run bar + live summary chips; tier assumptions basic/advanced; human copy.

**F-6 · P2 — Empty states: ~25 dead ends and 9 ad-hoc implementations remain.**
Dead-ends include **all five** animal-detail empties (`animals/[id]:1266,1306,1349,1410,1461`), the terse dashboard "None." states (dashboard:416,490,555), tasks board, both kidding queues, all three milk states, buckets, team, and simulation's four. The feeding history empty says "Clear or widen the dates" but renders no button (feeding:745). Ad-hoc markup (not the shared component): buckets:54, purchases:189/235, health:1317/1326, team:519/1121, milk:201, reports:317.
**Fix:** every list empty gets the shared component + a CTA when an action exists + copy branching "no data yet" vs "no matches"; add a "Clear filters" button where the copy already suggests it.

**F-7 · P2 — URL-state inconsistency and remaining un-backed filters.**
URL-backed: animals, tasks, finance (finance landed in the redesign ✓). Still component-state-only: feeding history date range + offset (feeding:299-301), health event offset (health:387), purchases offset + selected batch (purchases:280-281), simulation scenario offset (simulation:1158). Refresh loses them.
**Fix:** one `useUrlState` hook reused everywhere.

**F-8 · P2 — Team (newest RBAC UI) drift.**
- AddWorker, ResetPassword and Role dialog footers have **no Cancel button** (team:600-616, 701-712, 942-957) — dismissal relies on the X; other modules' create dialogs have Cancel.
- "Preset" chip is a hand-rolled `variant="warning"` Badge (team:1035) — the app's only non-test warning-variant use, bypassing StatusBadge and its dot.
- Preset roles being undeletable is explained **only** by a native `title` tooltip on the disabled Delete button (team:991-995, 1065); dairy-vs-goat preset scoping is explained nowhere in-product.
**Fix:** Cancel in all three footers; a proper chip via the badge system; one help line on the Roles card.

**F-9 · P2 — Raw enum leaks persist in three spots.**
- Dashboard move-suggestions render `→ {s.to}` — the raw bucket code (`dashboard:578`).
- Add-animal bucket select options (F-3).
- Simulation milk-projection marks a missed target **color-only** (`simulation:3876-3878`: identical numbers, only the text color changes).
**Fix:** `enumLabel` + a text/icon marker.

**F-10 · P2 — Vocabulary residuals (goat nouns on dairies).**
Verified in code, mostly in validation copy and secondary surfaces: breeding form errors "Select a **doe**" / "Select a **buck**…" (breeding:121,136); simulation labels `doe/buck/female_kid/male_kid`, "does per buck", "Doe scale…", "Adult doe and buck weights…" (simulation:565-568, 323, 1422, 1445, 3704, 4398); animals page "A buck/doe must be…" (F-3); animals/[id] "No **kids** recorded." (animals/[id]:1412); onboarding step copy "Tag every goat or buffalo" on a pure dairy (dashboard:217).
**Fix:** route all of these through `farmVocabulary` (the mechanism exists and works — see the shell).

**F-11 · P3 — Assorted.**
- Farm-switcher pill truncates farm names at 1440px (live-measured truncating span 177→174px; `max-w-72` in `app-layout-client.tsx:257`).
- Milk page re-declares generated models inline (`milk:102,410`) instead of importing `MilkDayTotalOut`/`MilkAnimalSummaryOut`; `payload!` non-null assertion (team:1203).
- `tabular-nums` hand-applied per-cell in milk/finance although the Table root already applies `table-numeric` (drift, not a bug).
- Sonner `toastOptions.classNames.toast: "cn-toast"` references a CSS class that doesn't exist (`ui/sonner.tsx:39-43`).

### B. Accessibility residuals (on a strong base)

**F-12 · P2 —** No skip-to-content link anywhere (keyboard users tab through the whole sidebar on every page).
**F-13 · P2 —** Heading skips: `EmptyState` renders `h3` directly under `h1`-only pages on ~11 pages (buckets, tasks, kidding, milk, health, breeding, purchases, dashboard, simulation, team, health/schedule). Make EmptyState's title a `p` or parameterize the level.

## 7. Remediation status (2026-09-01, same-day implementation)

Every finding F-1…F-15 plus the sorting remainder was implemented, test-adapted and verified. Five parallel implementation tracks (four page-group agents + main) followed the animals-page reference pattern.

### F-1 — Loading overhaul (P0) · **DONE, all 18 modules**
No page renders a bare "Loading…" paragraph as its content anymore. Every page mounts its real `PageHeader` + `PageSkeleton`/`TableSkeleton` while permissions or data settle (each with a polite sr-only announcement); sub-region loaders use a new shared `InlineLoading` (spinner + label). Background refetches keep the stand-down semantics (rows never misrepresent a stale filter/page) but now show the spinner line + skeleton instead of a bare text swap. Also fixed at the root: `use-permissions` treated the pre-farm auth window as "loaded", flashing "You don't have access" on first paint — `loading` now includes `farmId === null`.

### F-2 — Insight layer (P0) · **DONE**
Chart kit extended with `TrendChart` (signed bars), `LineChart`, `Histogram` (with reference markers) — all token-colored, dependency-free, accessible. Wired: milk page sparkline in "Today's herd total" + "Herd milk trend" line card (verified live, 8 days seeded); simulation Monte-Carlo NPV now renders on the shared `Histogram` with P5/P50/P95 markers and per-bin "runs" tooltips. `Sparkline`/`BarList` are no longer dead exports. (Finance P&L chart intentionally not fabricated — its API carries no monthly series; noted for a backend endpoint.)

### F-3 — Add-animal species fixes (P1) · **DONE, live-verified on the dairy**
Bucket dropdown options now species-labeled (`Quarantine / Heifers / Awaiting AI / Post-fresh / Heifer calves` — no raw codes anywhere, including the purchased-quarantine field and the list filter); breed input empty with placeholder "e.g. Murrah (the default when blank)" (no more Osmanabadi prefill); tag placeholder "B-7KP2D"; validation schema is a vocabulary factory mirroring `species.py` — live-verified: "BREEDING imports require a **milking buffalo** of at least **22 months and 340 kg**."; Cancel button + "* = required" legend in the footer; farm-select placeholder species-neutral.

### F-4/F-15 — Mobile + touch targets (P1) · **DONE**

### F-6 — Empty states (P2) · **DONE**
