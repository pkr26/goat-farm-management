# Backend Mutation Testing Report — 2026-09-22

Deep mutation testing of the FastAPI backend (`backend/app`), run fresh against
the full pytest suite (4,748 tests green at start; PostgreSQL/alembic-backed).

## Method

1. **Baseline**: full suite with per-test coverage contexts
   (`pytest --cov=app --cov-context=test`) — 4,748 passed, 4 skipped, 92.48%
   line+branch coverage, 42 min.
2. **Mutant generation** (`backend/mutation/mutate_gen.py`): AST-based, one
   mutation per site. Operators: comparison swaps (`==`↔`!=`, `<`↔`<=`,
   `>`↔`>=`, `is`↔`is not`, `in`↔`not in`), boolean swaps (`and`↔`or`),
   `not`-removal, arithmetic swaps (`+`↔`-`, `*`↔`/`, `//`→`*`, `&`↔`|`),
   `True`↔`False`, int off-by-one (`n→n±1`), ternary branch swap,
   `break`↔`continue`. Annotations/decorators excluded; string literals
   excluded (error-message noise). **6,730 mutants** across 90 modules.
3. **Execution** (`backend/mutation/mutate_run.py`): each mutant applied
   in-place (byte-exact restore, sha-verified) and run against only the tests
   whose coverage contexts cover the mutated line (escalating 15→60-test
   samples; hang = timeout-kill). 6 parallel workers, one throwaway Postgres
   DB each. 0 runner errors; working tree byte-identical afterwards.
4. **Verification**: all 345 survivors whose covering-test set exceeded the
   60-test sample cap were re-run against their **full** selections
   (400-cap). 270 of them were killed — i.e. corrected to KILLED; the
   remaining 75 are confirmed survivors. One 19-member random sample of
   ordinary survivors was also re-run (18/19 stable; the 1 flip is included
   in the corrections above).

## Curated findings (real test gaps, post-verification)

Ordered by risk. Each mutant listed survived its full covering selection.

### F1 — Lockout does not verifiably invalidate sessions (HIGH)
`app/api/auth.py:1809` — `locked_user.token_version += 1`.
Both `+= 0` (n→n-1) and `+= 2` survive. With `+= 0`, locking an account
(failed-login lockout) bumps no token version: already-issued access tokens
keep working for the remainder of their TTL and nothing in the suite notices.
Recommend a test: lock a user, then assert their pre-lock bearer token gets
401 (token_version check) — for both the lock and the unlock/re-lock path.
Same partial gap at logout (`auth.py:1506`, `+= 2` survives) and
owner-side lock (`api/team.py:1324`, `+= 2` survives).

### F2 — JWT key-pair completeness check degrades silently (HIGH)
`app/security.py:543` — `pair_complete = priv.exists() and pub.exists()`
→ `or` survives. With `or`, a half-written/deleted key file passes as a
complete pair. Bootstrap tests only cover both-present and both-absent.
Add: exactly-one-file-present → regeneration path (not a "complete" pair).

### F3 — Dashboard age-in-months math is fully unpinned (HIGH)
`app/services/dashboard.py:92-94` — all six mutations of
`months = (y - dob.y) * 12 + (m - dob.m)` (incl. `*`→`/` and `+`→`-`)
survive, plus the `months -= 1` day-of-month adjustment. Every age-derived
dashboard figure could be computed with broken arithmetic and pass the suite.
Add exact assertions for age in months across year boundaries and
before/after the day-of-month anniversary. The same unpinned pattern exists
in `services/simulation_calibration.py:55` and `services/finance.py:68,586`.

### F4 — Feeding: dependent-kid (creep) boundary conditions (MEDIUM-HIGH)
`app/services/feeding.py:280,283` — `age_days <= weaning_days` → `<` and the
dam-join `==` → `!=` survive. Kids exactly at weaning age, and the
dam-linked filter of the creep ration, are untested edges; wrong creep feed
allocation is invisible. Add boundary tests at exactly `weaning_days` and
with/without a lactating dam.

### F5 — Lifecycle transitions lose audit attribution silently (MEDIUM-HIGH)
`app/services/tasks.py:556,574,596,617` — swapping
`created_by_id=user.id if user else None` survives for quarantine release,
postpartum recovery, gestation-day-100 step-up, and pre-delivery moves.
The moves themselves are asserted; **who** performed them never is.
Assert `created_by`/audit attribution on task-generated bucket moves.

### F6 — Calibration curve interpolation unasserted (MEDIUM)
`app/services/simulation_calibration.py:172-175` — the linear-interpolation
core (`lower`/`upper` neighbor selection `a < age` / `a > age`, `span =
upper - lower`, and the lerp `+`/`*`) mutates freely between preset age
points. Calibrated growth/mortality curves can be interpolated wrongly
without detection. Add point-tests between preset ages with exact expected
values (currently only the preset points themselves are pinned).

### F7 — Screening policy limits and vision thresholds unpinned (MEDIUM)
`app/api/screening.py:74-83,353-354` — `MAX_OPEN_SCREENING_BATCHES_PER_FARM`
(5), `MAX_SCREENING_IMAGES_PER_BATCH` (100),
`MAX_IN_FLIGHT_SCREENING_IMAGES_PER_FARM` (250), list default/max limits
(25/200), `SCREENING_STATS_MAX_DAYS` (365), `SCREENING_EXPORT_MAX_RECORDS`
(5000): every ±1 survives. `services/screening/detect.py:26,28` —
`MIN_BOX_SIZE` (40) and `MAX_DETECTED_GOATS` (20) likewise.
`services/screening/gate.py:23` — `MAX_OBSERVATIONS` (8) likewise.
These are abuse/DoS budgets and ML-gate quality knobs; pin each at its
boundary (value passes, value+1 fails / 422).

### F8 — Rate-limiter internals: reclassification and sweep scheduling (MEDIUM)
`app/ratelimit.py:149,227,283` — `touch=True`→`False` on `_reclassify` and
`_next_sweep = clock() + interval` → `-` survive. Bucket heat promotion and
background sweep timing are behaviorally unasserted; drift here surfaces as
stale limits or unbounded memory. Add a test with a fake clock asserting a
sweep runs at the scheduled time and reclassifies touched buckets.

### F9 — Security-relevant config defaults unpinned (MEDIUM)
159 of the 500 `config.py` survivors sit on security-relevant defaults no
test pins, e.g. `access_token_ttl_seconds` (30 min), argon2 cost parameters,
`auth_rate_limit_max_attempts` (10) / window (300 s),
`worker_pin_rate_limit_*`, `screening_daily_call_budget_per_farm` (400),
`max_request_body_bytes` (1 MiB). Tests that exercise these paths always
set env explicitly. A defaults-regression test (construct `Settings()` with
a scrubbed env and assert the shipped values) would kill the whole class.

### F10 — Misc confirmed gaps (LOWER)
- `app/deps.py:95` — `request.client.host if request.client else 'unknown'`
  branch swap survives: IP fallback for rate-limit/audit keys unpinned.
- `app/deps.py:165` — security-event `expired=False`→`True` survives (audit
  detail).
- `app/api/team.py:499` — password-reset policy flag `False`→`True` survives
  (policy gating asserted only on the happy path).
- `app/api/auth.py:502-503` — refresh-cookie flags (`httponly`/`secure`
  wiring) survive mutation; only cookie *presence* is asserted.
- `app/api/auth.py:418` — `content_type.split(';', 1)` maxsplit mutants
  survive (media-type parameters edge).
- `app/services/notifications/service.py:542` — "critical" escalation
  threshold `(reference - due).days >= 3` boundary unpinned.
- `app/services/finance.py:146` — `round(net, 2)` → `round(net, 3)` survives
  (rounding precision of money figures).
- `app/services/dashboard.py:141-277` — readiness-window comparisons
  (`<=`→`<`, `>=`→`>` on rebreeding-rest, withdrawal, market windows).
- `app/api/owner.py` — benchmark aggregation: SQL column-index swaps in dict
  builds (`row[1]`→`row[2]`) and `cost_per_kg` guard boundaries survive;
  the owner console's numbers are not asserted anywhere.

## Equivalent-mutant classes (no action)

- `break`→`continue` inside bounded `for _ in range(n)` guard loops
  (e.g. `api/_shared.py:293` exception-chain walk) — behaviorally identical.
- 605 type-annotation mutants (`str | None` → `str & None`) were purged from
  the manifest before scoring (mypy/ruff territory, zero runtime signal under
  `from __future__ import annotations`).
- Logging-argument arithmetic (`attempt + 1` in retry log lines), message
  truncation counts (`rows[:5]`, `> 5` ellipsis).
- Dead-value defaults shadowed by env in every test (majority of
  `config.py`).

## Reproduce

```bash
cd backend
.venv/bin/python mutation/mutate_gen.py                       # regenerate manifest
COVERAGE_FILE=.coverage-mut .venv/bin/python -m pytest -q --cov=app \
    --cov-context=test --cov-report= -p no:cacheprovider      # contexts (42 min)
.venv/bin/python mutation/mutate_run.py --workers 6           # campaign (resumable)
.venv/bin/python mutation/mutate_report.py                    # report.md
```

Artifacts: `backend/mutation/{manifest.json, results.jsonl, report.md}`,
`backend/.coverage-mut` (202 MB contexts DB — safe to delete; needed only to
re-run the campaign). Every app source was restored byte-exact after each
mutant (sha-verified; `git status` clean at completion).

## Caveats

- Verdicts for covering sets > 400 tests are based on a 400-test spread
  sample (round-robin across covering files). The 345-survivor full-selection
  re-verification showed a ~5% false-survivor rate before correction; the
  corrected numbers above incorporate it. Ordinary (≤ 60-test) survivors were
  spot-checked, not exhaustively re-run — treat individual survivors as
  "needs a test until proven equivalent", which is the actionable reading.
- Timeout-kills (106) count as killed; a handful may be slow-but-finite
  mutants rather than true hangs.
- Mutation score is a property of *this operator set*; it complements, not
  replaces, the 92.48% line+branch coverage ratchet.
