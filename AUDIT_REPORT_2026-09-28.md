## PART 1 — NEW BUGS (fix first)

### CRITICAL

**C1. `/api/auth/worker-login` is missing from both auth route tables — a wrong PIN wipes the offline queue and ejects the tablet to the manager login**
`frontend/src/lib/api-client.ts:768-778` (`NO_REFRESH_PATHS`) and `:631-641` (`REFRESH_COOKIE_POST_ROUTES`). The backend worker-login sets a refresh cookie and its 401 *is the answer* ("Invalid PIN."), same class as `/api/auth/login` — which is in both tables with dated re-audit comments. Worker-login (added 2026-09-22) was never added. Three consequences, all verified:
- On the normal pinned-tablet state (no session cookie), a wrong PIN → 401 → refresh attempt → rejected → `onAuthFailure` → `clearSession()` → **`wipeOfflineQueue()` + redirect to `/login`** — a PIN typo destroys queued field writes from a prior shift and kicks the worker off the PIN pad.
- With a live cookie, the transparent refresh retries worker-login, **double-charging the server-side PIN lockout budget** (`backend/app/api/auth.py:1147-1160` records per request).
- Its Set-Cookie response bypasses the cross-tab auth-cookie lock, reopening the response-order cookie race.
**Fix:** add `/api/auth/worker-login` to both sets; add a test asserting a worker-login 401 performs no `/api/auth/refresh` call. (`worker/page.test.tsx:35-49` mocks `useAuth`, and `test/msw-server.ts:81` always answers refresh successfully — both mask this today.)

### HIGH

**H1. `sw.js` pins tablets to the install-time build forever** — `frontend/public/sw.js:8,42-56`. `CACHE = "herdly-worker-v1"` is constant across deploys and the `/worker` shell is cache-first with no revalidation: sw.js stays byte-identical → no install event → cached HTML keeps referencing old hashed chunks. Tablets silently run a stale client against a newer backend indefinitely. Fix: inject a build hash into the cache name (or network-first/stale-while-revalidate for HTML) and surface reload on `updatefound`.

**H2. Queue drain drops records on 401/408/429** — `frontend/src/lib/offline-queue.ts:247-252`. The comment says "(403/404/422): retrying cannot fix it" but the code drops **every 4xx**. An expired access token whose refresh is momentarily *unavailable* (5xx/timeout/captive portal — explicitly transient per `api-client.ts:819-823`) throws the original 401 and the field-recorded write is deleted forever; 429s are dropped instead of backed off. Fix: keep-and-stop on 401/408/429; drop only 403/404/422-class answers. Related: queued records have **no TTL** (`:225-256`) — a same-actor re-login weeks later replays stale completions.

**H3. Worker-PIN throttles are all IP-keyed — PIN guessing is distributable** — `backend/app/api/auth.py:1097-1114,1147-1160`. Both scopes key on `_client_key(request)` (IP); rotating source addresses reset both budgets. Password login deliberately closes this hole with the IP-agnostic `login-email` scope (`auth.py:137-143,289`). With the 6-digit production floor and the unauthenticated roster handing out `membership_id`s, ~100 rotating IPs yield ~2.9M guesses/day against one membership. Fix: add an IP-agnostic per-membership bucket mirroring `login-email`. Companion issue: **a successful worker-login resets the farm-wide spray bucket** (`auth.py:1191-1193`) — the sibling login path deliberately never does this (`auth.py:340-345` comment); drop the spray reset.

**H4. CI lint gates are red on main right now** — verified by lead auditor on clean HEAD `5d7c22b`: pinned ruff 0.16.1 reports **39 lint errors** (E501×20, F401, F841, RUF100, E741, SIM105, C408, PTH123, UP037 across `mutation/` and the `*_gaps.py` test files) and **12 files would be reformatted**. The last two commits landed without running the gate. Fix first, before anything else merges: `ruff format` + `ruff check --fix`, then hand-fix the rest.

**H5. Worker board renders raw English duty titles on the Telugu-first surface** — `frontend/src/app/worker/page.tsx:62` (`{task.title}`). The backend ships `title_key`/`title_args` and `resolveTaskTitle(task, language)` exists for exactly this; `tasks/page.tsx:305,407` and `dashboard/page.tsx:437` use it, the worker DutyCard never imports it. Auto-generated duties (the bulk of a worker's board) render English to the Telugu-first audience. Fix: `resolveTaskTitle(task, language)` in DutyCard.

**H6. ~25 query/mutation error sites render raw English backend `detail`, bypassing the `mapServerError` contract** — e.g. `buckets/page.tsx:177`, `tasks/page.tsx:855,1147`, `purchases/page.tsx:256,543`, `kidding/page.tsx:1036,1129`, `health/page.tsx:1146,1783`, `breeding/page.tsx:1007,1068`, `feeding/page.tsx:501,924`, `finance/page.tsx:747`, `team/page.tsx:1695`, `animals/page.tsx:1485`, `animals/[id]/page.tsx:1519,1746,2251`, `simulation/page.tsx:3310`, `components/remote-picker.tsx:420`, `register/page.tsx:90`. `dashboard/page.tsx:196` does it right. Only 4 codes + 8 pinned phrases translate (`lib/server-error-phrases.ts:22-40`); everything else is English server prose for Telugu users. Fix: funnel all `ApiError.detail` rendering through `mapServerError`.

**H7. Nine major surfaces still ship hardcoded English UI — 451 whitelisted literals in the gate baseline, and the scanner can't see whole classes** — gate-verified truth (`frontend/src/lib/i18n/english-literal-baseline.json`, ceiling 457): `animals/[id]/page.tsx` 101, `planner/page.tsx` 54, `purchases/page.tsx` 50, `finance/page.tsx` 49, `team/page.tsx` 38, `feeding/page.tsx` 37, `animals/page.tsx` 29, `breeding/page.tsx` 27, `kidding/page.tsx` 21. Worse, `scripts/scan-english-literals.mjs:32-40` misses expression-container strings (`{busy ? "Saving…" : "Add"}`), non-whitelisted attributes (`emptyMessage`, `helperText`), default-parameter strings, toasts, and zod messages — so the true inventory is materially larger than 451. Fix: extend the scanner, regenerate the baseline, then convert pages namespace-by-namespace as `health.*` did.

## PART 2 — MEDIUM FINDINGS

### Notifications subsystem (new since last audit — 4 real defects)

- **N1 [bug] Per-farm daily SMS cap defeated inside one fan-out batch** — `services/notifications/service.py:78-91,199-201` + `:179-194`. Sessions run `autoflush=False` and `record()` only does `db.add()`, so `_farm_send_count_today` sees only committed rows; a digest run with N recipients sends N SMS regardless of `notifications_farm_daily_cap`. Fix: `await db.flush()` after each `record()`, or count in-session pending rows.
- **N2 [bug] Day-dedupe is check-then-insert with no conflict handling** — `service.py:165-194` vs `uq_notification_log_day_dedupe`. Two concurrent sessions both pass the probe, both send (real money); the loser's commit raises IntegrityError, aborting the whole farm digest *after* earlier SMSs went out — and the rolled-back log rows get re-sent next minute-tick. Sibling code uses `pg_insert(...).on_conflict_do_nothing()` for exactly this (`services/tasks.py:777-801`, `feeding.py:217-225`). Fix: claim via ON CONFLICT before sending.
- **N3 [bug] Alert hooks leak an httpx client per alert** — `services/notifications/hooks.py:27` builds a fresh `Msg91Provider` (own `httpx.AsyncClient`, `providers.py:85`) per `emit_alert`, never closed — the exact leak class the last audit fixed for screening providers. Fix: module-level cached provider or `try/finally: aclose()`.
- **N4 [inconsistency] Notification tables bypass the tenant-isolation + CHECK program** — `models/notifications.py:59-85`, `alembic/versions/e5a7c9d1b3f5_notifications.py:58-94`. `notification_log.recipient_id` is a bare single-column FK (no `(farm_id, id)` candidate key on recipients → cross-farm pointer possible via direct SQL); no CHECKs on `alert_class`/`status`/`phone`/`local_date`; `local_date` is `String(10)` while every other date column is `Date`; `provider_message_id`/`error` typed `Mapped[str]` but `nullable=True`; singular table name among plural siblings. Also: **console provider logs phone + full SMS text at INFO** (`providers.py:61`) — PII in dev/staging logs.

### Backend security (mediums)

- **S1 [security] Account export emits no security event** — `api/auth.py:1630-1710`. The most PII-dense response in the API leaves no `security_event` trail; audit.py's docstring names document downloads as in-scope and DPR download got one (`planner.py:504-510`). Fix: emit `auth.account.exported`.
- **S2 [inconsistency] `worker_login` holds a `FOR UPDATE` lock + pooled connection across the Argon2 verify** — `api/auth.py:1117-1145`. Violates the module's own stated invariant ("Argon2 never holds a row lock, transaction, or checked-out DB connection", `auth.py:878-890`). Each guess pins the user's row for a full memory-hard verify. Fix: snapshot → rollback → verify → re-lock + revalidate, exactly as `login` does.
- **S3 [dead-code] `active_membership(lock_authorization=True)` branch is dead** — `deps.py:365-422`; both call sites use the default. Dead code that reads like a live authorization control invites wrong pin-order by future callers. Delete it.
- **S4 [security] Recovery-code redemption leaks unused-code count via timing; up to 10 sequential Argon2 verifies per request with no reservation** — `api/auth.py:2622-2655`. Observer needs a valid MFA token, so impact is small; add a reservation or constant-work note.
- **S5 [inconsistency] `/totp/challenge` lacks the explicit `_require_json_content_type` guard** its login-flow siblings carry (`auth.py:2540` vs `:787,861,1081`); it sets the same refresh cookie. **Worker-login 403s contradict the "same generic 401" docstring** (`auth.py:1172-1188` vs `:1093-1094`) — a correct PIN on a TOTP/must-change account is distinguishable; tested as deliberate, so fix the docstring. **MFA jti replay cache is in-memory** (`auth.py:2001-2018`) — a restart inside the 300s TTL allows one replay; document or DB-back it. **worker-roster records to the limiter even when limiting is disabled** (`auth.py:1041-1046`) — the only ungated `record`.
